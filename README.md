# Расширение браузера ELOUP для FACEIT (#258, #288, #289)

**v0.3.5** — пакет, готовый к публикации в Chrome Web Store: `php build.php` собирает
`dist/eloup-extension-0.3.5.zip` без прав на локальные адреса, а записи `[ELOUP]` в
консоли страницы FACEIT включаются только флагом `debug`. Поведение на странице —
как в v0.3.4.

**v0.3.4** — разбор демки FACEIT в один клик с самой страницы матча, бейджи
игроков ELOUP в комнате и быстрый разбор из истории матчей:

- кнопка **«Разобрать на ELOUP»** под «СМОТРЕТЬ ДЕМО» в комнате матча
  (если FACEIT переставил вёрстку — плавающая справа внизу);
- бейдж **«ELOUP · роль»** со знаком ELOUP у игроков, зарегистрированных на
  платформе (матчинг по SteamID64 из ростера, ник — запасной), с карточкой
  профиля по клику — карточка показывается публичным профилям, скрытые дают
  просто бейдж «ELOUP». Ник важнее бейджа: там, где плашка теснит имя (строка
  игрока в комнате), бейдж сворачивается до одного знака, роль — в подсказке;
- в истории матчей — плитка разбора в каждой строке (встаёт в саму строку,
  а не падает под список), все состояния — фирменным знаком (ломаная роста):
  тёмная плитка с жёлтым знаком — демку можно отправить; знак мигает — идёт
  передача (процент — в подсказке) или разбор; залитая жёлтым — разбор
  готов, по клику открывается; красный «!» — сбой, причина в подсказке;
- тумблер **«Каждый разбор сразу на ИИ»** в попапе (PLUS/staff): демки
  передаются с флагом `ai_review`, и сервер сам заказывает ИИ-разбор
  сразу после метрик;
- после «Обновить» или отключения расширения открытые вкладки FACEIT не сыплют
  ошибками: прежняя копия скрипта замолкает сама, кнопки и бейджи вернутся
  после перезагрузки страницы.

Расширение качает демку матча с сессией игрока и передаёт её на eloup.gg
кусками — без сохранения на диск. Дальше работает обычный конвейер разбора:
метрики, счёт, 2D-реплей; ИИ-разбор игрок заказывает на странице катки или
включает тумблер в попапе — тогда (PLUS/staff, с согласием на передачу
данных ИИ и бесплатным планом на момент разбора) он запускается сам.
Разбор фокусируется на нике FACEIT игрока: расширение находит его в ростере
матча по SteamID аккаунта ELOUP (`state` отдаёт `user.steam_id`) и передаёт
серверу с первым чанком. Сервер подстраховывается сам: если фокуса нет в
таблице счёта демки, `ParseDemoAnalysis` уточняет его по `players[].steam_id`.

Бейджи и ростер (разведка 24.11): `match/v2` держит фракции сразу в
`payload.teams` (без `factions` из Data API v4), SteamID64 игрока — поле
`gameId`. Диагностика — логами `[ELOUP]` в консоли страницы, только с флагом
`debug` (см. «Сборка пакета для Chrome Web Store»).

Клиентская часть расширения — этот отдельный репозиторий; серверный приём
демок (`ExtensionDemoController`, токены) — в основном репозитории eloup.gg.

Зачем это нужно: демки FACEIT — приватный ресурс. `demo_url` из Data API
указывает на хост, который намеренно не резолвится, а официальный Downloads
API — отдельная заявка на ~30 дней без гарантий. Браузеру залогиненного
игрока ссылки видны, поэтому транспортным агентом выступает расширение.

## Как устроено

- `manifest.json` — Manifest V3, чистый JS без сборщика. Права: `storage`
  (токен, тумблер ИИ, флаг `debug`); `www.faceit.com` / `api.faceit.com`
  (данные матча и подпись ссылки на демку), `*.backblazeb2.com` (сам файл демки
  по подписанной ссылке), `eloup.gg` (приём); `localhost` и `127.0.0.1` — только
  для локальной отладки, в пакет для магазина их убирает `build.php`.
- `content.js` — кнопка «Разобрать на ELOUP» под «СМОТРЕТЬ ДЕМО» в комнате матча
  (`/cs2/room/{matchId}`; MutationObserver цепляется к кнопке FACEIT, через 4 с
  без якоря — плавающая справа внизу), бейджи «ELOUP · роль» у игроков десятки
  и плитки разбора в истории матчей (`/players/*/stats/*` и
  `/players/*/cs2/history`). Стили в shadow DOM; бейдж и плитки сидят на
  собственных тегах `<eloup-badge>` / `<eloup-tile>` — FACEIT перекрашивает
  `button`/`span` страницы важными объявлениями (так плитки становились
  белыми), а внутрь тени и на чужой тег его CSS не достаёт. FACEIT отводит
  контейнеру ника немного места и усекает имя, когда дети не помещаются
  (полная плашка оставляла игрока с двумя дефисами вместо ника), поэтому
  бейдж после вставки измеряет имя: усекается — сворачивается до знака
  (`data-compact`); пересобирается на `resize` и при мутациях страницы.
  Он же добывает подписанную ссылку на демку (схема ниже): запросы идут со
  страницы матча — same-origin, с куками сессии FACEIT. Все вызовы
  `chrome.runtime.sendMessage` идут через `send()`: расширение обновили или
  отключили (`Extension context invalidated`) — скрипт снимает таймеры и
  наблюдателей и больше не трогает API.
- `background.js` — service worker: транспорт. Принимает от кнопки подписанную
  ссылку, стримит её `fetch → reader` одним потоком и конвейером шлёт чанки на
  `POST /api/extension/demos` (Bearer-токен, 16 МиБ на кусок — размер приходит
  из state; пока кусок едет, сеть уже читает следующий). 409 с фактическим
  размером — рестарт с новым идентификатором и свежей подписью (TTL ссылки —
  5 минут, фоновый воркер запрашивает её у страницы матча).
- `popup.html` / `popup.js` — токен и адрес сайта, проверка связи и тумблер
  «Каждый разбор сразу на ИИ» (строка настройки: включён — фирменная заливка
  #ccff00; пишется в `chrome.storage.local.aiAuto`, background шлёт флаг
  `ai_review` с каждым куском демки).
- `icons/` — 16/48/128, фирменный знак ELOUP: ломаная роста из логотипа
  (геометрия `public/favicon.svg` сайта), круглая плитка #0f0f10, градиент
  #e8ff66 → #ccff00 → #a3d100. Пересборка: `php icons/build.php` (нужен PHP
  с GD; прозрачность углов проверит `php icons/check-alpha.php`).

Серверная часть — в основном репозитории eloup.gg: `ExtensionDemoController`
(`routes/api.php`), токен — Sanctum PAT с правом `extension`, выдаётся во вкладке
настроек «Катки» (`PremierController::issueToken`). Дедуп — по `source_ref = match_id`.
Бейджи — `ExtensionPlayerController::lookup` (`POST /api/extension/players/lookup`,
лимит `extension-lookup` 10/мин): расширение присылает ростер десятки — ники и
SteamID64 — а сервер по каждой записи ростера отвечает, зарегистрирован ли
игрок на ELOUP (`eloup`) и карточку для публичных профилей: имя, роли
(`PlayerRole`), любимую карту, число видимых хайлайтов и адрес профиля.
Матчинг — SteamID из ростера (точный), ник — запасной; карточку отдаём только
публичным (`hasPublicProfile` — согласие на распространение или сотрудник),
скрытые получают бейдж без раскрытия личности. `faceit_id` — в будущем.

## Установка (для теста)

1. `chrome://extensions` → включить «Режим разработчика» → «Загрузить
   распакованное расширение» → выбрать эту папку.
2. На eloup.gg: настройки профиля → вкладка «Катки» → «Создать токен»,
   скопировать.
3. Иконка расширения → попап → вставить токен → «Сохранить и проверить».
4. Открыть страницу сыгранного матча FACEIT — справа внизу кнопка
   «Разобрать на ELOUP». Для локального сайта сменить адрес на
   `http://localhost` (нужно `APP_URL` и работающий веб-сервер).

## Сборка пакета для Chrome Web Store (v0.3.5)

Из корня репозитория:

    php build.php

Итог — `dist/eloup-extension-<версия>.zip` (папка `dist` не попадает в git). В пакет
входят только рабочие файлы: манифест, `background.js`, `content.js`, `popup.html`,
`popup.js` и три иконки. Сборка сама проверяет пакет и останавливается с ошибкой,
если:

- в репозитории остался рабочий файл, не попавший в пакет (например, новый скрипт,
  который забыли подключить);
- манифест или страница расширения ссылается на отсутствующий файл;
- `name` длиннее 75 или `description` длиннее 132 символов, `version` — не от одной
  до четырёх групп цифр (это проверяет сам магазин);
- манифест в архиве отличается от репозитория чем-то, кроме прав на локальные адреса,
  либо в архиве есть пустой файл, PHP-скрипт или README.

Манифест в пакете — манифест репозитория без прав на `localhost` и `127.0.0.1`: из
папки репозитория расширение ходит и на локальный сайт, из магазина — только на
FACEIT, Backblaze и eloup.gg. Повторная сборка того же кода даёт байт в байт тот же
архив, в конце печатается его SHA-256.

Перед загрузкой в магазин распакуйте архив в пустую папку и откройте её через
«Загрузить распакованное расширение»: так проверяется именно то, что уйдёт на
проверку.

### Диагностические логи

Записи `[ELOUP]` в консоли страницы FACEIT выключены по умолчанию. Включить в своём
браузере: DevTools расширения (`chrome://extensions` → «Service Worker» или попап) →
консоль → `chrome.storage.local.set({ debug: true })`. Флаг читается при загрузке
страницы и подхватывается на лету; выключить — `chrome.storage.local.set({ debug: false })`.

## Как FACEIT отдаёт ссылку на демку (разведка 23.11, DevTools)

Схема двухшаговая, оба запроса идут со страницы матча с куками сессии:

1. `GET https://api.faceit.com/match/v2/match/{matchId}` — из данных матча
   берём неподписанный `resourceUrl` (`demo_url` / `demoUrl` / `demoUrls[0]` /
   `demoURLs[0]`; хост `demos-…faceit-cdn.net` намеренно не резолвится — качать
   его нельзя, только подписать).
2. `POST https://www.faceit.com/api/download/v2/demos/download-url` с JSON
   `{"resourceUrl": …}` и заголовками сайта (`accept: application/json+camelcase`,
   `content-type: application/json`, `faceit-referer: web-next`) — ответ
   `payload.downloadUrl`: подписанный S3-адрес Backblaze, **TTL ~299 секунд**
   (`X-Amz-Expires=299`). Авторизации заголовком нет — достаточно кук
   (`credentials: 'include'`).
3. `GET downloadUrl` — сам файл `.dem.zst` (zstd; сервер ELOUP принимает),
   `Content-Length` есть — прогресс показывается.

### Капча — гигиена запросов (v0.3.0) и открытый риск

Сайт прикладает заголовок `x-faceit-captcha-token` (Cloudflare Turnstile).
23.11 FACEIT начал отвечать **403** на `POST download-url`, если расширение
стучится слишком часто. Гигиена в v0.3.0:

- JSON матча кэшируется в `sessionStorage` на 10 минут (ростер для бейджей
  не добавляет ни одного запроса к FACEIT);
- подпись ссылки кэшируется ~4 минуты (TTL подписи — 299 с);
- между `POST download-url` — минимум 15 секунд, конкурентные вызовы ждут;
- на 403 — один автоповтор через 30 секунд, дальше человек: кнопка просит
  нажать родную «СМОТРЕТЬ ДЕМО» и повторить.

Проверено 23.11 владельцем: челлендж **невидимый** — капчу не видно и не
вводить, но после ручного клика по «СМОТРЕТЬ ДЕМО» расширение заработало
без каких-либо действий с капчей (клик по нативной кнопке валидирует
браузер в глазах FACEIT).

План Б (если не хватит) — инжект скрипта в main world и запуск Turnstile-
виджета FACEIT со страницы (sitekey есть на room-странице), токен передавать
в тот же заголовок. Отдельная задача.

## Чего нет (осознанно)

- Фонового агента «все матчи сами» — кнопки только на открытых страницах.
- Очереди передач и догрузки после закрытия вкладки: service worker живёт,
  пока идёт `fetch`, но вкладку с матчем лучше не закрывать.
- Уведомлений о готовности: разбор открывается кнопкой «Открыть разбор».
- Автопрокрутки Turnstile (план Б выше) и матчинга по `faceit_id` — SteamID
  из ростера покрывает основную потребность.
